# 确认、修改与继续

模块进入 **等待输入**（`waiting_input`）时，工作页会显示结构化表单。回答表单后继续当前运行，不需要创建新项目。

## 执行前确认

AI 会列出本次目标、输入、范围、方法、预算、风险和预期产出。检查它是否符合你的要求，再选择：

- **批准执行** → 点击 **批准并继续**。
- **修改方案** → 填写具体修改意见，再点 **提交修改意见**。

![实验模块的执行前确认表单](/img/current/module-approval.png)

*当前确认表单组件截图，方案文字为演示。实际内容由本次模块生成。*

调研、规划、实验、交付都有自己的确认范围。点击启动模块后出现确认表单属于正常流程。批准前，模块只能做允许的本地只读检查与提出交互；正式检索、执行、写文件和发布结果需要通过当前确认。

选择修改后，AI 会修订方案并再次请求确认。之前批准过的旧方案不能代替对修订后方案的批准。

## 过程中可能多次提问

同一个模块可先澄清目标，再询问数据边界，之后请求范围批准。新的问题出现时，按新表单回答；先前的回答已保存，不需要把所有内容重新发送。

一般澄清问题可选推荐项、填写补充说明，或在允许自由回答时直接输入决定。执行确认需要明确选择批准或修改；修改意见不能为空。

## 手动实验的继续决定

![每个实验结束后的继续或结束选择](/img/current/manual-continuation.png)

*当前交互组件截图，提示内容为演示。*

- **继续下一个实验**：授权再执行一个已登记实验。
- **结束并汇总**：汇总已有结果，剩余提案可标为跳过，不再运行新的实验。

最后一个实验结束后也会询问，以便你先检查结果再完成本模块。详见 [实验输入与执行](./experiment-inputs.md)。

## 提交失败或刷新页面

交互问题和已接受的回答由后端持久化。提交时遇到断线、旧 revision 或已过期的交互，应重新加载当前 Run，确认哪一个问题仍未回答。不要仅根据聊天中的“我会继续”判断提交是否成功。

**暂停**、**取消模块** 与回答表单不同：暂停后可在允许的检查点继续；取消是结束当前运行。停止按钮和服务停止的区别见 [快速对话](./quick-chat.md) 与 [本地服务](../../deployment/local-engine-service.md)。
