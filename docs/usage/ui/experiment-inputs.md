# 实验输入与执行

> 每次实验的手动/自动选择和额外输入路径在 **MiraUI 0.4.5rc1 + MIRA 0.3.5rc1** 中提供。

## 在启动窗口中设置

从总览直接启动实验，或从上游候选继续实验，都能看到 **实验执行模式**、**额外输入路径**，并可填写运行目标。总览启动窗口还提供指标停止条件、实验最大次数与 Token 上限。

## 手动与自动

| 模式 | 行为 |
| --- | --- |
| 自动（默认） | 在批准的范围和配置限制内连续执行实验 |
| 手动 | 第一个实验获批后执行；每个实验结束并保存记录后，等待你决定继续一个实验或结束并汇总 |

手动模式的边界是 **登记的实验**，并非每次模型回复、工具调用或操作系统进程。一个脚本里不能偷偷包装多个实验来绕开逐次确认；实验应先登记，再执行。

同一手动 Run 只允许一个实验处于运行中。保存 `completed` / `failed` / `skipped` 记录后触发继续决定；编辑已经保存的终态记录不会重复产生该边界。确认状态可在刷新后恢复。

这个设置保存到本次 Run 的 `module_data.experiment_execution_mode`，与总览 **模块完成后** 的下游衔接策略独立。旧 Run 没有该字段时使用自动语义，旧项目的全局 `run_mode` 不能覆盖它。

需要在正在执行的实验中途停下时，用任务停止或模块暂停/取消；逐次确认是在实验记录结束后发生的。

## 额外输入路径

![项目外输入路径的填写区域](/img/current/experiment-input-controls.png)

*当前路径输入组件的局部截图。*

可以填写数据、文章或代码的 **文件/目录绝对路径**，再用“添加路径”加入其他输入。最多 32 项，空项忽略，重复路径会归并。

1. 路径必须存在且可读取。
2. 路径指向 **gateway 所在机器**。远程部署时，本地电脑上的 `/Users/...` 不是服务端路径；Docker 中使用容器内挂载路径。
3. UI 会验证路径；正在验证或存在无效项时不能启动。
4. 项目外路径会显示范围提示，即使开启 workspace 限制，本次实验也可获准读取该输入。

启动后，所填路径只授权 **本次实验及其子智能体读取**。它不授予外部写入权限，也不会自动授权其他 Run。处理后数据、指标和交付文件应写到项目的允许目录。

路径限制是运行时工具层的检查，不能当作操作系统级隔离。只选择任务确实需要读取的范围；填一个文件或数据子目录通常比整个磁盘更清晰。

## 停止条件与预算

首次尝试建议选择手动模式，并为运行填写明确的实验次数和 Token 上限。指标条件需要使用实际结果中的指标名，填写比较符和值；AND 表示全部条件，OR 表示任一条件。

预算和阈值不代替数据、参考标准、验证划分和结果审查。自动模式仍需执行前批准，也可因等待输入、失败或限制而停止。更多参数见 [Automation Policy](../agent-config/automation-policy.md)。
